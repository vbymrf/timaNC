> Карточка `entity_message` — **сущности не пишут в личку**, их сообщения приходят только сюда. В MVP отправляют владельцы/админы сущности (`POST /inbox/notify`) и система; с появлением Bot API — боты (`notifyUser`). «Скрыть источник» = `block_messages` сущности.

**Карточка обращения показывает:** identity (какой ВП / основной аккаунт), источник, отправителя, preview, статус, ответственного, действия.

| Действие | Смысл |
|----------|-------|
| Открыть | Обращение к **ВП** → настоящий E2E-чат (бейдж ВП + панель оператора). Обращение к **сущности** → публичный тред обращения (бейдж сущности; ответы атрибутируются сущности — «Канал X», независимо от того, ответил оператор или бот). Карточка `entity_message` → просмотр сообщения + ссылка |
| Взять | assignee = я (виден всей команде) |
| Отложить | snooze до времени; карточка вернётся |
| Закрыть | Обращение решено; из «Входящих» уходит |

> **Статус и ответственный — серверные**, общие для владельца и операторов ВП. Статусы: `new → taken → snoozed → closed`.
> События основного аккаунта (реакции, упоминания) — личные: у них только прочитано/скрыть, «Взять» не показывается.

### Панель оператора (при «Открыть» обращение к ВП)

- Полный разговор открывается как **настоящий личный чат** `human ↔ virtual_user`
- Боковая панель: статус (`new` / `taken` / `snoozed` / `closed`), ответственный, заметки
- Ответ подписывается ключом ВП; получатель видит только ВП
- Окно 4 не дублирует тело сообщений — только metadata и ссылки на `chat_id` или `thread_id`

## Состояния

> **Empty («Входящие»):** «Нет новых обращений» + [Настроить правила].
> **Нет ВП:** вкладка «Входящие» показывает только события основного аккаунта; подсказка «Создайте виртуального пользователя» → настройки ([25-settings-help-bugs.md](./25-settings-help-bugs.md)); создание ВП не требует блогерского режима (окно 6 — лишь один из UI для управления ими).
