# Product Requirements (PRD)

## 1. Видение

**TIMA** — мессенджер-комбайн: единая среда для личного общения, новостных лент, медиа, социальных взаимодействий и real-time звонков на Android, iOS и Windows.

## 2. Персоны

| Персона | Потребность |
|---------|-------------|
| Обычный пользователь | Личные E2E-чаты, звонки, ленты, медиа |
| Участник сообщества | Подписка на сообщества, группы, каналы, аудиочаты, реакции |
| Блогер | Виртуальные пользователи (ВП), статистика, рекламный кабинет (окна 6–7) |
| Оператор compliance | Контролируемый escrow-доступ по юридическому запросу |

## 3. Scope платформ

| Платформа | In scope | Out of scope (v1) |
|-----------|----------|-------------------|
| Android | API 26+ | — |
| iOS | 15.0+ | — |
| Windows | Windows 10+, Desktop (KMP), MSIX | — |
| Web | — | Клиент и привязка Web не входят в release scope |
| macOS/Linux | — | Не в v1 |

## 4. Функциональные блоки (из концепции)

Этот раздел фиксирует **функциональное видение продукта**, а не обязательный объём ближайшего релиза. Binding release scope, порядок поставки и exit gates определены в [roadmap.md](../09-delivery/roadmap.md); функция считается обещанной к релизу только при включении в соответствующую фазу.

### 4.1. Пять базовых окон

1. **Телефон** — контакты, личные чаты 1:1 (E2E), звонки.
2. **Новостная лента** — три вкладки: **общая лента** (формирует сервер: скоринг + атрибуты/жанры), **лента друзей** (публичные полки избранного друзей), **каталог**; **сообщества** (admin-контейнеры), группы (E2E/private, public), каналы, threads, аудиочаты. Папки каталога — только персональная организация, не сообщества. Модель лент: [feed-ranking.md](../04-data/feed-ranking.md). Канон: [social-objects/00-index.md](./social-objects/00-index.md).
3. **Медиа-лента** — Lenta/Slides; public и E2E-коллекции.
4. **Социальное взаимодействие** — stories; агрегатор входящих ВП и социальных событий (вкладки: Входящие, Мои треды, Реакции, Коллекции); настраиваемые правила `social_inbox_preferences`; серверные статусы обращений `new → taken → snoozed → closed`. Канон ВП: [social-objects/virtual-user.md](./social-objects/virtual-user.md). UI: [10-free-communication.md](../doc_UI/10-free-communication.md).
5. **Личная страница** — профиль, избранное (**две полки**: публичная / личная 🔒), подписки, роли. См. [feed-ranking.md](../04-data/feed-ranking.md) §2.

### 4.2. Специализированные окна

- Окно 0 — активный звонок/аудиочат (временное).
- Окна 6–7 — режим блогера (медиа/новости).
- Настройки, помощь, баги.

### 4.3. Инварианты коммуникации

- **Сущности не пишут в личку**: группа, канал, сообщество и Bot Application **не могут** создать личный чат (окно 1). Адресные сообщения сущности пользователю приходят **карточками в окно 4** (`entity_message`: `POST /inbox/notify`, позднее Bot API `notifyUser`). `POST /appeals` создаёт отдельное обращение и не является транспортом `entity_message`. Окно 1 — строго «человек ↔ человек» (включая ВП как полноценный аккаунт). Пер-пользовательская настройка `block_messages` отключает карточки от сущности; уведомления — отдельно.

### 4.4. Сквозные механики

- Универсальный редактор: [+]/[−] (только публичное → общая лента), **шкала 9 эмоций** для оценки любого контента (8 валентных эмоций пополняют раздельные рейтинговые счётчики «+»/«−», нейтральная в рейтинг не входит), ответ, пересылка, отложенная отправка. Канон: [18-content-actions.md](../doc_UI/18-content-actions.md).
- **Атрибуты (= хэштеги)** и **жанры** — тематические срезы общей ленты; одобрение меток `declared` → `approved` | `rejected`. UI: [34-attributes-genres.md](../doc_UI/34-attributes-genres.md).
- Избранное (две полки), глобальный поиск, QR/инвайты.
- Push (3 уровня), attestation (iOS/Android), Windows через QR + телефон.
- Мультиустройство, архив, экспорт чата.

## 5. Non-goals (v1)

- Web-клиент как полноценная платформа.
- MLS/Wormhole для групп (используем Sender Keys поверх Kodium).
- Application-level E2E для звонков (см. [ADR-0006](../adr/0006-livekit-media-policy.md)).
- Самописная MTProto/TDLib-подобная БД на старте (PostgreSQL + object storage).

## 6. Матрица приватности (краткая)

Полная таблица: [content-security-matrix.md](./content-security-matrix.md).

| Контент | Шифрование на клиенте | Escrow |
|---------|----------------------|--------|
| Личные чаты, private groups, private collections | Да | Да (controlled) |
| Public groups, channels, public media | Нет | N/A |
| Звонки, аудиочаты | SRTP (не app E2E) | По политике записи |

## 7. Целевое состояние Communication MVP

Функциональная цель этого раздела поставляется по фазам и не заменяет exit gates roadmap. Communication MVP соответствует **Phase 2**; social, bot, compliance и release readiness поставляются последующими фазами.

- **Полный аккаунт:** регистрация SMS + обязательный email + 10 резервных кодов; attestation; QR для Windows.
- **Временный режим:** гостевой аккаунт без телефона/email, одно устройство, TTL 30 дней неактивности; апгрейд до полного ([key-lifecycle.md](../03-security/key-lifecycle.md) §13, [22-auth-registration.md](../doc_UI/22-auth-registration.md)).
- Текстовые сообщения 1:1 и группы с доставкой offline через wrapped keys.
- Загрузка медиа (client-side encrypt → MinIO).
- Аудио/видео звонки 1:1 и группа до 20+ через LiveKit SFU.
- Голосовые сообщения (Kodium → MinIO), не через LiveKit Egress.
